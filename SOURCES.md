## Reproducibly generated GB18030 BMP mapping
For this release, the distribution mapping is adopted from an independent run of generate_gb18030_map.py, rather than relying on an asserted historical origin. The original table's earliest generation method remains unknown.

T04 reconstructed the table with CPython 3.13.5. Reviewer 03 separately ran the supplied generator with CPython 3.12.14 and verified all 262144 output bytes against the embedded table, including the 2048 zero surrogate entries. Both reconstructions produce SHA-256 a0aae8f074ce932296493ea19d022024fb37973087654a40bfd27ee2a60e2dde. The adopted regenerated bytes are identical, so the reviewed application HTML is unchanged.

Representation: BMP U+0000–U+FFFF; each code point stores a little-endian uint32 whose integer value packs its encoded bytes in big-endian order. ASCII NUL is represented by zero and handled separately by the application. Surrogates are invalid scalar values and map to zero placeholders.

This release targets the recorded CPython codec behavior. It does not claim compliance with every revision of the GB18030 standard or byte-identical behavior to every browser decoder. When regenerating with another Python version, compare the entire output and investigate differences before release.
